第 00 章

读前说明：这本书怎么读

源码快照 2026-09-22 · 约 8 分钟

LangChain 和 LangGraph 最容易学错的地方，不是 API 太多，而是入口太多。搜索结果里同时存在 0.x 的 Chain 教程、1.x 的 Agent 工厂、LangGraph 的 Graph API、Functional API，以及依赖不同模型供应商的样例。每一段代码单独看都像是正确答案，拼在一起却常常跑不起来。

这本书换一种路线：先固定版本和源码，再建立执行模型，最后才谈应用模式。

本书回答什么#

读完后，你应该能独立回答五个问题：

  1. LangChain 和 LangGraph 各自负责哪一层？
  2. 一次工具调用在消息、模型、工具和状态之间如何流动？
  3. StateGraph 为什么需要 reducer，compile() 又编译了什么？
  4. checkpoint、store、interrupt 和 stream 的边界在哪里？
  5. 出现重复副作用、状态膨胀、恢复异常时，应从哪段源码开始查？

本书不会罗列每个 provider 的参数。模型名称和价格变得很快，消息协议、状态转换和持久化边界更值得掌握。

跟着一份状态读，而不只记住名字#

读正文时，可以始终想象同一个研究任务：用户提问，模型要资料，工具返回笔记，图形成草稿，人决定是否发布。遇到新概念，先看它改变了这条路径的哪一部分，再读类型与源码入口。

消息章节追请求与结果的身份；状态章节追哪个字段何时可见；运行时章节追任务如何推进；持久化和中断章节追两次调用之间靠什么连接。后面的生产边界并非额外规则，而是前面机制在超时、重复和升级时会遇到的后果。正文用具体状态推演和失败情景展开，速查表放在需要回看时再读。

源码快照#

本书以 2026-09-22 的两个官方仓库为基线：

项目 提交 本书对应包

LangGraph 1afaca35a0d4 langgraph 1.2.12、langgraph-checkpoint 4.2.0

本地浅克隆位于 sources/repos/langchain 与 sources/repos/langgraph。版本以后一定会变化，所以正文把内容分成三类：

  • 稳定心智模型：消息、工具循环、状态更新、super-step、checkpoint 与 store 的职责。
  • 当前 API：示例中的导入路径和函数签名。
  • 版本提示：beta 接口或快照中新出现的能力，例如 DeltaChannel。

遇到当前 API 与未来版本不一致时，先保留心智模型，再去官方 reference 核对名字。

阅读路线#

想尽快做出 Agent#

读第 1、2、4、6、7、10、14 章。你会得到一条从工具循环到带记忆图的最短路径。

想读懂框架源码#

按顺序读完全书。第 5 章的 Runnable 和第 9 章的 Pregel 是连接表层 API 与运行时的两座桥。

正在排查线上问题#

直接看第 9 至 15 章。大部分问题属于四类：状态合并、恢复重放、副作用幂等、事件消费。

示例约定#

书中使用“本地研究助手”作为贯穿案例。它读取本地资料、形成草稿，并在发布前等待人工审批。选择这个例子有三个原因：

  • 不需要付费模型也能验证控制流；
  • 同时覆盖循环、路由、并行、持久化和中断；
  • 容易区分框架行为与模型能力。

examples/mini_agent.py 只使用 Python 标准库，展示最小工具循环。examples/research_assistant.py 使用真实 LangGraph API，但模型与资料仍是确定性的，因此测试不会受网络和随机输出影响。

如何看源码引用#

每章末尾的“源码入口”只列最值得打开的文件，不追求逐行覆盖。推荐采用三步法：

  1. 先读公开类型和 docstring，确认输入输出。
  2. 再读构建阶段，看对象如何被组装。
  3. 最后跟运行阶段，看状态何时可见、何时被持久化。

不要一上来从 6000 行的基类顺序往下读。带着问题找调用链，比统计读过多少文件更有效。

本书是独立撰写的学习材料。外部教程仅用于比较教学顺序，正文、图解、示例业务和代码均重新组织。完整来源见附录。
