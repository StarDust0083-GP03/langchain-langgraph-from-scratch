# Deep Agents：create_agent 之上的 harness

一份较长的观测研究可能需要整理资料文件、维护待办、调用窄专家并压缩历史。只用 `create_agent` 也能逐项实现，但许多项目会重复搭建同一组外围能力。Deep Agents 将这些能力组合为 harness，入口通常是 `create_deep_agent`。

它继续利用 LangGraph 的执行机制。新增的是默认工具、策略和上下文组织方式，不是另起一套检查点或中断系统。本章涉及独立 `deepagents` 包及官方文档，具体签名应按安装版本核对，不能从两个核心仓库的提交推断全部实现。

## create_deep_agent 默认装了什么

官方描述强调 planning、subagents、filesystem 和 context management。可以按观测研究的实际工作理解这些模块：

| 模块 | 对申请研究可能有用的能力 | 必须另行确认的边界 |
| --- | --- | --- |
| `FilesystemMiddleware` | 读取资料、维护研究附件和检索文件 | backend 可读写范围及是否允许执行 |
| `SummarizationMiddleware` | 压缩早期研究交互 | 摘要是否保留来源和未决项 |
| `SkillsMiddleware` | 按需加载仪器研究流程 | 技能来源、可信性与加载成本 |
| `TodoListMiddleware` | 记录待核验规则和任务进展 | 勾选完成不等于证据正确 |
| `SubAgentMiddleware` | 委托窄范围资料核验 | 子任务权限、预算与失败返回 |

默认组合会随版本变化，能力也可能受 backend 支持限制。采用前应检查实际暴露的工具列表，尤其是文件删除、命令执行和外网访问；不要因为是官方 harness 就跳过权限审查。

## 从零搭一遍，看清每块补什么

原官方教程以数据分析讲逐步组装，这里改用“为 Halpha 申请整理研究附件”的教学设计，不声称已经运行沙箱。先用标准循环只返回资料摘要，再依据真实缺口加能力：

| 研究遇到的缺口 | 可增加的模块 | 接入后的最小检查 |
| --- | --- | --- |
| 资料附件要保存并再次读取 | 文件 backend 与文件中间件 | 只访问工作目录，路径越界被拒绝 |
| 多轮修订挤掉早期规则 | 摘要中间件 | r1 来源、1500 秒预算和未知项仍在 |
| 仪器流程只在少数任务用到 | 技能中间件 | 未命中时不载入全文，命中后可找到来源 |
| 多个来源各需独立研究 | 子 Agent 与待办 | 子任务有窄输入、结束状态和预算 |

组装关系可用下面的伪代码表达，类名和构造参数应按实际版本选择，不把它作为可直接运行的调用：

```python
research_harness = assemble(
    base_agent=standard_model_tool_loop,
    filesystem=restricted_workspace_backend,
    summarizer=source_preserving_summary,
    skill_sources=[approved_instrument_skills],
    delegates=[filter_rule_reviewer],
)
```

只有明确需要整套默认组合时再选择 `create_deep_agent`；若只缺摘要，直接为现有 Agent 配置相应中间件更容易控制变化。每增加一项能力，先验证一个允许案例和一个拒绝或失败案例。

## 沙箱是边界，不是可有可无

文件中间件提供操作入口，backend 决定操作实际发生在哪里。内存状态型、宿主文件系统和远程隔离执行环境不是同一种安全边界。`LangSmithSandbox` 是文档中的一种沙箱选项，不代表所有文件 backend 都自动具备同等隔离。

为观测研究配置沙箱时，明确可挂载的资料、网络出口、命令权限和资源额度。虚拟路径不等于可靠隔离，路径校验、符号链接、宿主挂载和凭据注入都需检查。若服务允许执行命令，能力面远大于几个文件工具。

研究附件也不会自动回到主机或长期保存。任务结束前应选择需要保留的文件，记录来源版本和内容指纹，再经受控接口导出。沙箱销毁与 checkpoint 保留的生命周期不同，恢复时还要处理附件已不存在的情况。

## 技能用渐进披露省 token

技能启动阶段通常只暴露名称和描述，需要时才加载完整说明。下面是一份教学技能文本，演示领域流程的组织，不是仪器操作规程：

```markdown
---
name: observatory-budget-review
description: 为模拟观测申请核对曝光、读出和校准预算
---
读取当前申请参数，保留原始单位。
查找已批准的开销资料及其 revision，再计算总秒数。
报告窗口余量，并列出未包含的真实观测条件。
不执行排班预留，不把计算通过写成人工批准。
```

技能降低常驻上下文成本，不会消除载入后的 token 开销，也不会自动增加工具权限。技能内容若包含脚本或外部命令，应按来源可信度审查。一个写着“可以读取全部主机目录”的说明，不应改变 backend 授权。

## 子 Agent 隔离的是上下文

可以委托子 Agent 核验一批滤镜资料，让它内部进行查询和修正，只向主助手返回来源版本、限制与未决项。主上下文不必承载每轮失败和重试，能减少干扰。

隔离上下文不等于隔离所有权限或进程。子 Agent 可能共享模型、工具 backend 或存储，取决于配置；审计系统也可能保留其完整轨迹。不能绝对声称主流程永远看不到中间细节，应区分模型收到的委托结果与开发者可访问的观测记录。

需要精确控制每个恢复位置、公开输入输出和并行聚合时，显式子图更容易检验。只需把一段窄研究收敛成结果对象时，中间件委托可以减少组装，但仍要处理超时、预算和不完整结果。

## 什么时候不需要 Deep Agents

两条教学规则加一个预算计算没有文件工作区、长历史或多专家需求，普通 `create_agent` 或确定性图就足够。本书端到端例子选择后者，是为了把审批和停止条件写清楚。

若业务顺序严格，不能让 Agent 随意决定何时结算或提交，应在外层状态图固定边界。只用一块通用能力时，单独配置比整套默认 harness 更容易审计。选择依据是实际缺口和测试结果，不是名字中是否带 deep。

## 源码入口

- `deepagents` 的 `create_deep_agent`：核对当前版本实际添加了哪些能力。
- `deepagents/middleware/`：分别查看文件、摘要、技能、子任务与待办的合同。
- `deepagents/backends/`：检查存储路径、执行支持与隔离责任。
- 官方 `deep-agent-from-scratch`：用于对照逐步组合方式，不沿用其数据分析案例。

阅读后可列一张“实际工具、backend 权限、状态字段、失败出口”的清单，再决定观测研究需要启用哪几项。没有沙箱实测时，只描述设计与文档合同，不给出隔离或性能已经验证的结论。
